> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 学習とうまさをほめるバッジ（38種類・86段、冒険なしで26種類・66段）と称号を、新しいファイル `badges.js`・`badges.css` で 195か国ドリルに足す。index.html への追加は `<link>` と `<script>` の2行だけ。

**Tech Stack:** 素の HTML/CSS/JS（ビルドなし）、テストは `node --test`（Node 22。単体は `vm`）と Playwright（`createRequire` でグローバルのもの）。

**Spec:** `docs/superpowers/specs/2026-10-26-badges-design.md`（これが正。以下「設計書」）。イベントの約束は計画 B が書いた `docs/events.md`。

  - `pickResult(detail) -> r`（`outcome kind region mode n wrongs attempts best timeMs hint` だけ。数は `| 0`、`timeMs` は数か `null`、`hint` は `!!`）

    - `['ans', a, right, first, hint, mode, missesBefore, missesAfter]`
    - `['res', r, dopa, day]`（`r` は `pickResult` の戻り値）
    - `['book', a]`、`['wk-reset']`
    - `['rpg', t, p, day]`（`t` は `coins levelup join promote answer battle clear overcome bounty`、`p` は `pickRpg` の戻り値）
    - `['got', key, time]`（まだ無ければ入れる）、`['sent', key]`（まだ無ければ足す）、`['eq', key|'']`（`''` か `KEY_RE` に合うものだけ）、`['seen', id, time]`（`sn[id]` を大きいほうに）、`['tip']`（`tip` を +1、最大3）

`pickRpg` が返すもの（数は `| 0`、真偽は `!!`）:

| t | 返すもの |
|---|---|
| `coins` | `{}`（呼ぶ側が `reason === 'start'` のときだけ積む） |
| `levelup` | `{ lv }` |
| `join` | `{ via, owned }` |
| `promote` | `{ learn }`。`learn = detail.via ? detail.via === 'learn' : (detail.star === 2 && screen !== 'gacha')` |
| `answer` | `{ a, right, mode }` |
| `battle` | `{ boss, win, mistakes, revived, maxCombo, lv, recLv }` |
| `clear` | `{ dungeon }` |
| `overcome` | `{ a }` |
| `bounty` | `{ totalDays }` |

`apply` の中身は設計書 §3.3 の表と `applyResult` `addDay` のコードどおり。補足:
- `ans`: 国コードが `X.codes` に無ければ何もしない。正解なら `s.right++`、不正解なら `s.wk[a] = 1` で終わり。ヒントありならここで終わり。`MODE_BIT[mode]` を `s.m[a]` に OR。`first` なら `(mb > 0 || s.wk[a]) && ma === 0` で `s.ov[a] = 1`、そのあと `delete s.wk[a]`
- `rpg answer` は `mode` が `f2n n2f m2f` のときだけビットを立てる（`cap` などは正解数だけ）。不正解は `wk` を付けるだけ
- `rpg battle` は `addDay(s, day)`、`s.streak = max(s.streak, maxCombo)`、`win`→`rpg.win = 1`、`boss && win && mistakes === 0`→`nodmg`、`boss && win && lv <= recLv - 5`→`under`、`revived && win`→`phoenix`
- `rpg clear` は `X.DUNGEONS` にある id だけ、`s.rpg.boss` に重ねずに足す

`sanitize` の範囲は設計書 §7.1 のとおり。補足: `clears` は 0..1e7、`tip` は 0..3、フラグ（`grit back dopa fever` と `rpg.start win nodmg under phoenix friend master`）は 0 か 1、`last` は `/^\d{4}-\d{2}-\d{2}$/` に合わなければ `''`、`rc` の値は 0..3、`sn` のキーはバッジ id の形だけ残す、`got` `sent` は最大500件: `got` は時刻（値）の大きい500件を残す（同じ時刻なら元の並びで後ろのものを残す）、`sent` は配列の後ろの500件を残す。`migrate(obj, X)`: オブジェクトでない（`null`・配列・数）なら `{ d: fresh(), ro: false }`。`v` が `VERSION` より大きければ `{ d: sanitize(obj, X), ro: true }`。それ以外は `MIGRATE[v]`（いまは空の `{}`）を順に当ててから `sanitize(obj, X)`。
