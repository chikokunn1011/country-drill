# サイト共通のプロフィール Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 冒険だけにある1端末1登録のプロフィールを国旗マスター全体の共通プロフィールにし、タイムアタック・今日の難問・冒険のランキングをすべてそのプロフィールで載せる（引き継ぎコード・公開プロフィール窓・非公開設定つき）。

**Architecture:** Supabase に `profiles`・`profile_transfers` を足し、3つのランキング表に `profile_id` を足す。書きこみはすべて合言葉（token）で本人確認する新しい security definer 関数（`*2` / `*3`）。ブラウザ側は新しい `profile.js` が localStorage `profile`・プロフィール画面・結果画面の「載せる」箱（`postBox`）・ランキングの名前セル（`nameHTML`）・プロフィール窓（`openCard`）・引き継ぎを持ち、`index.html`（TA）・`daily.js`・`rpg-rank.js` はそれを使う。

**Tech Stack:** 素の JS（クラシック script、ビルドなし）、Supabase（PostgreSQL 16 / PostgREST RPC）、node:test（unit・vm）、Playwright（e2e、偽 Supabase は tests/e2e/helpers.mjs）、tests/sql/run.sh（使い捨て PG16）。

**Spec:** `docs/superpowers/specs/2026-10-28-profile-design.md`（チコ OK 2026-10-28 07:38Z）

## Global Constraints

- 画面の文言はすべて日本語・タメ口（今のサイトと同じ口調）。コメントも日本語で、まわりのコードと同じ密度。
- 名前は前後空白を除いて1〜12文字（絵文字も1文字）・NGワード（`ranking.js` NG_WORDS と schema.sql `ng_words()`）。**ほかのプロフィールと同じ名前は不可**（`lower(normalize(nickname, NFKC))` で比べる）→ reason `name_taken`。
- 合言葉は端末で作る UUID。DB には `rpg_hash(token)`（sha256）だけ。token が null/空なら `bad_token`。プロフィールが無い（引き継がれた）なら `not_found`。
- 公開用ID `pid` は12文字の英数字（合言葉とは別）。ランキングの行に出すのは pid だけ。
- 引き継ぎコード: 12文字、文字は `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（0/O/1/I なし）、表示は `XXXX-XXXX-XXXX`、入力はハイフン・空白・小文字を許す。24時間有効・1回だけ。出し直すと前のコードは無効。出すのは1分に1回まで（`too_soon`）。預けるデータは 512KB（`octet_length(p_data::text) <= 524288`）まで（`too_big`）。
- 預ける localStorage キー: `settings`・`setup`・`misses`・`nickname`・`rpg`・`badges`・`daily`・`bdgcat`・`bview`。預けないキー: `profile`・`profilePending`・`rpgRank`・`rpgRankPending`・`rpgRankDel`・`rpgSent`・`rpgUnreg`・`transferBackup`・`transferPending`・`badges-broken`（と管理ページの `adminSnaps`・`adminErrors`・`adminAuth`）。形は `{ v: 1, keys: { キー: 文字列 } }`。
- かざりは `rpg_codes()` の国コード・3つまで・重複なし。称号は40文字まで。バッジの数は 0〜500。
- 自動で載せる（`auto`）と公開（`is_public`）は、はじめ ON。
- ランキングに名前の横のかざりは出す、称号は出さない。pid の無い古い記録の名前は押せない。
- 古い関数（submit_score / submit_daily / rpg_register / rpg_rename / rpg_update / rpg_set_deco）は drop せず、中身を `{"ok":false,"reason":"old_version"}` に入れかえる。テーブル・列・関数は消さない。
- schema.sql は何度流しても大丈夫なまま（`if not exists`・`create or replace`・引っ越しは `where not exists`）。
- 本番の SQL: 中に delete を含む関数（`rpg_unregister2`）は schema.sql の `-- >>> SQL Editor` 〜 `-- <<< SQL Editor` の間に置く（チコに SQL Editor で Run してもらう）。古い関数の入れかえは `-- >>> old_version` 〜 `-- <<< old_version` の間（サイト公開の後に流す）。
- e2e は `--test-concurrency=1`、`tests/e2e` で `npm ci` 済みのこと。playwright install はしない。
- クラシック script どうしで名前がぶつからないよう、`profile.js` は IIFE の中に書き、外に出すのは `window.PROFILE` だけ。
- キャッシュよけ: 変えた js/css の `?v=` を1つ上げる。

## Review Focus

1. 引き継ぎで受け取ったデータに一覧外のキーや壊れた値がある → 一覧のキーの文字列だけ書き戻し、ほかは無視（Task 6 のテスト `claim ignores unknown keys`）。
2. 自動で載せる途中でつながらない・`too_soon` → 結果画面に［もう一回送る］が出て、押せば同じ記録を送り直せる（Task 4 の `postBox retry`）。
3. 前の端末で引き継ぎ後に TA をクリア → `not_found` で `PROFILE.lost()`、知らせを1回だけ出し、結果画面はプロフィールを作るフォームに変わる（Task 7 のテスト `lost after transfer`）。
4. ランキングの名前に `<script>` などが入っている → `nameHTML` が esc して文字として出す（Task 5 の `nameHTML escapes`）。
5. 2つのタブで同時にプロフィールを作る・変える → `storage` イベントで `profile` を読み直して表示をそろえる（Task 4 の `storage sync`）。

**Interfaces:**
- Consumes: Task 3 の `RANKING.profile*`、index.html の `store`・`$`・`esc`・`registerScreen`・`show`・`toast`・`emit`。
- Produces（`window.PROFILE`）:
  - `get()` → `{token, pid, name, auto, isPublic} | null`
  - `create(name)` → `Promise<{ok, reason?}>`（token は `profilePending` に先に覚え、`already` が返ったら `profileMe` で取りなおす。成功で `nickname` にも書く）
  - `rename(name)` → `Promise<{ok, reason?}>`
  - `setAuto(bool)`・`setPublic(bool)`（公開は profileSet で送る）
  - `auto()` → `boolean`（プロフィールがあって auto が ON）
  - `lost()` → プロフィールを消し、toast「このプロフィールは別の端末に引き継がれたよ」を1回、`profile:change` を出す
  - `postBox(el, { label, send })` → 結果画面の「載せる」箱を el に描く。`send(token)` は `Promise<{ok, reason?, text?}>`（text は成功の文）。プロフィールあり＋auto → すぐ send、あり＋auto OFF → ［載せる］、無し → 名前入力（`nickname` を入れておく）＋［プロフィールを作って載せる］。失敗は `RANKING.message(reason)` と［もう一回送る］。`not_found` なら `lost()` して箱を描き直す。返り値は `{ retry() }`
  - イベント `profile:change`（detail `{ profile }`）: 作る・名前変更・lost・引き継ぎで出す
  - localStorage `profile`: `{ token, pid, name, auto, isPublic, sent: { isPublic, title, deco, badges, badgesTotal } }`
