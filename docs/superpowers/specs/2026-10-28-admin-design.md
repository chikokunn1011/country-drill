# 管理用サイト 設計書

- 日付: 2026-10-28
- 対象: 国旗マスター（https://chikokunn1011.github.io/country-drill/）
- 状態: チコのレビュー待ち（いらない機能は消してOK。§3 の表の「番号」で言ってくれればいい）

## 1. 目的

チコだけが使える管理用ページを作る。2つの役目がある。

- **デバッグ**: 開いた端末のセーブデータ（冒険・バッジ・今日の難問・設定など）を見る・変える・戻す。演出や効果音の確認。
- **ランキングの管理**: タイムアタック・今日の難問・冒険（英雄の塔をふくむ）・プロフィールの記録を見る・消す・名前を変える。

チコの要望と決定（2026-10-28）:
- 「デバッグ、ランキング操作などができるサイトを作って」（08:38Z）
- 守り方は「ログイン＋管理者チェック」（08:41Z 決定）
- 「できるだけいろんな便利な機能をつけて」（08:42Z）

## 2. 安全のしくみ（いちばん大事）

サイトは公開リポジトリの GitHub Pages で、Supabase の公開用キーはサイトに埋め込み済み。つまり**管理ページの HTML もキーも誰でも見られる**前提で作る。ページを隠すことでは守らない。

### 2.1 ログイン

- Supabase Auth のメール＋パスワード。チコのユーザーは Supabase の画面（Authentication → Users → Add user）でチコが作る。
- **新規登録はオフ**（Authentication → Sign In / Providers → 「Allow new users to sign up」をオフ）。チコが画面で切りかえる。
- 万一オフにし忘れて誰かが登録できても、§2.2 の管理者リストにいないので何もできない（二重の守り）。
- （おまけ・あとで足せる）2段階認証（TOTP、Google Authenticator など）。入れたら管理関数は `aal2` のときだけ通す。§3 の番号 S8。

### 2.2 サーバー側のチェック

- 新しいテーブル `admins (user_id uuid primary key)`。RLS ON・ポリシー無し。チコの user_id を1行だけ入れる（SQL Editor で）。
- 管理用の関数は全部 `admin_` で始まり、security definer。最初に `admin_check()` を呼ぶ:
  - `auth.uid()` が null（ログインしていない＝公開用キーだけ）→ エラー
  - `admins` にいない → エラー
- 権限: `revoke all ... from public, anon` → `grant execute ... to authenticated`。anon（今のサイトのキーだけ）では呼べない。authenticated でも `admin_check()` で弾く。
- **service_role キー（強い鍵）はブラウザにも GitHub にも置かない。** 管理ページが持つのは「公開用キー＋チコのログインの合札（JWT）」だけ。
- 消す・名前を変えるなどの操作は全部 `admin_log` テーブルに残す（だれが・いつ・何を・前の値）。

### 2.3 ページ側の守り

- ランキングの名前は他人が入れた文字なので、管理ページで**絶対に HTML として入れない**（全部 `textContent`）。ここで穴があると、名前に仕込んだスクリプトがチコのログイン中に動いてしまう。
- 外のスクリプトは読まない（d3 なども使わない。素の JS だけ）。`<meta http-equiv="Content-Security-Policy">` で `script-src 'self'`・`connect-src` を Supabase だけに。
- ログインの合札は `sessionStorage` に置く（タブを閉じたらログアウト）。`localStorage` だと本編のページからも読めてしまうので使わない。
- `<meta name="robots" content="noindex">`。sitemap.xml には入れない（robots.txt にも書かない。書くと場所を宣伝することになる）。
- 何もしないまま30分たったら自動でログアウト。

### 2.4 デバッグ機能（端末のセーブ）はログイン不要

端末のセーブデータは、その端末の localStorage にしかなく、誰でもブラウザの開発ツールで書きかえられる。守る意味がないので、§3 の「端末」の機能はログインなしで使える（ランキングの記録はサーバーが値をチェックするので、セーブをいじっても変な記録は載らない。今と同じ）。

## 3. 機能の一覧

場所: `admin.html`（`https://chikokunn1011.github.io/country-drill/admin.html`）。本編と同じオリジンなので、その端末のセーブデータに直接さわれる。タブで切りかえ、スマホでも使える。

### 3.1 端末（デバッグ、ログイン不要）

| 番号 | 機能 | 中身 |
|---|---|---|
| D1 | セーブ一覧 | localStorage のキー（settings / rpg / daily / profile / badges 系 / misses / nickname / rpgRank など）と大きさ・最終更新を一覧（最終更新は、セーブの中に時刻・日付が書いてあるもの〔badges・rpg・daily・adminSnaps・adminErrors〕だけ。localStorage 自体は更新時刻を持たないので、ほかは出さない） |
| D2 | セーブを見る・書きかえる | キーを選ぶと JSON を整形して表示、そのまま編集して保存（形が壊れていたら保存しない） |
| D3 | バックアップ | 全部を1つの JSON ファイルにダウンロード／ファイルから読み戻す（読み戻す前に今のを自動でバックアップ） |
| D4 | スナップショット | 「今の状態を保存」→ 名前つきで5個まで覚えておき、ワンタップで戻す（テストのやり直し用） |
| D5 | 冒険 | コイン ±、Lv を決める、ダンジョンごとのフロア解放、全部解放、ボスを倒したことにする、ストーリー既読を消す、ガチャの天井カウンター、カードをあげる、冒険データを消す（今の `?rpgdebug=1` パネルの上位互換） |
| D6 | 英雄の塔 | 最高到達階・いまの階を決める（塔が本番に入ってから） |
| D7 | バッジ | 全部取る／全部消す／1個ずつ取る・消す、称号を選ぶ |
| D8 | 今日の難問 | 今日（と好きな日付）の20問と答えを見る、この端末の「今日はもうやった」を消してもう一回できるようにする |
| D9 | 設定 | テーマ・音・ドパガキ・国名表示などをまとめて切りかえ、初回状態（はじめての人）に戻す |
| D10 | 演出テスト | ガチャ演出・紙吹雪・コンボ・効果音を1つずつ鳴らす／出す（本編を開いて試すボタン） |
| D11 | 画面ジャンプ | 本編の好きな画面を直接開くリンク（冒険・図鑑・ランキング・今日の難問・`?rpgdebug=1` など） |
| D12 | 端末の情報 | ブラウザ・画面の大きさ・ダーク/ライト・動きを減らす設定・localStorage の使用量・オンラインか・Supabase につながるか |
| D13 | エラー記録 | 本編で起きたエラー（window.onerror）を端末に最新50件だけ残し、ここで見る・コピー・消す（本編に数行足す） |
| D14 | データ点検 | 195か国の国旗・地図・地域・豆知識がそろっているか自動チェック（抜け・重複・地図に無い国を一覧） |

## 4. 作り

### 4.1 ファイル

- `admin.html` … 画面（タブ: 端末／ランキング／プロフィール／ログ）。CSS も中に。
- `admin.js` … 画面の動き。
- `admin-api.js` … Supabase への通信（ログイン・合札の更新・`admin_` 関数の呼び出し）。fetch だけで、supabase-js は使わない（外のスクリプトを読まないため）。
- `admin-save.js` … 端末のセーブの読み書き・バックアップ・スナップショット（DOM にさわらない、テストしやすく）。
- 本編の変更は少しだけ: D13 のエラー記録（index.html に数行）。冒険の操作は今ある `RPG.debug` と同じ形を、セーブ（localStorage `rpg`）に直接書く形で `admin-save.js` に持つ（本編を開いていないときも使えるように）。本編の別タブが開いていれば storage イベントで描き直される（今の作りのまま）。

### 4.2 Supabase

- 新しいテーブル: `admins`・`admin_log`・`admin_trash`・`ng_words`（S10）。どれも RLS ON・ポリシー無し。
- 新しい関数: `admin_check`・`admin_stats`・`admin_list(p_kind, p_filter)`・`admin_delete(p_kind, p_ids)`・`admin_restore(p_trash_ids)`・`admin_rename(p_kind, p_id, p_name)`・`admin_set_public`・`admin_suspicious`・`admin_ng_*`・`admin_log_list`・`admin_transfers`（S11）。
- `ng_words()` は中身を `ng_words` テーブルから読む形に入れかえる（create or replace。今のリストはテーブルに最初から入れる）。
- 中に delete がある関数は、MCP では確認待ちで時間切れになるので**チコに SQL Editor で Run してもらう**（今までと同じ）。それ以外は MCP の apply_migration。
- テスト: `tests/sql`（ローカル PG16）で、anon・ログインしただけの人・管理者の3通りで呼んで、前の2つは必ず弾かれることを確かめる。

### 4.3 共通プロフィール・英雄の塔との順番

ランキングの形は今、別スレッドの「共通プロフィール」（profiles＋profile_id）で変わっている途中。英雄の塔も rpg_players に列を足す予定。ぶつからないように2段階で出す:

1. **第1弾（すぐ作れる）**: 端末のデバッグ（D1〜D14、D6 は塔が入ってから）＋ログインのしくみ（admins・admin_check・admin_log）＋今あるテーブルの閲覧・削除・名前変更（S1〜S4、S6、S7、S12〜S14）。
2. **第2弾（共通プロフィールが本番に入ってから）**: S5・S9・S10・S11 と、ランキングの表示をプロフィールの名前に合わせる。`admin_list` などの中身をプロフィール後の形に入れかえる。

第1弾の関数は、プロフィールで足される列（profile_id）を知らなくても動く書き方にする（列を名前で選ぶ）。

## 5. チコにやってもらうこと（本番に入れるとき）

1. Supabase の画面で自分のユーザーを作る（メール・パスワード）。
2. 新規登録をオフにする。
3. SQL Editor で、こちらが渡す SQL を Run（`admins` にチコの user_id を入れる行もふくむ）。
4. PR をマージ（チコの OK のあと）。

手順は画面の名前つきで別に書いて渡す。

## 6. やらないこと

- 他の人を管理者にする機能（必要になったら SQL で `admins` に1行足すだけ）。
- 管理ページから本編のコードや設定（Supabase のキーなど）を変えること。
- 他の人の端末のセーブを変えること（それはできないし、しない）。
