# タイムアタック＋みんなのランキング 設計書

- 日付: 2026-10-25
- 対象: 195か国ドリル（https://chikokunn1011.github.io/country-drill/）
- 状態: チコのレビュー待ち

## 1. 目的とゴール

いろんな人に遊んでもらうために、「タイムを競う」遊び方と、遊んだ人のタイムが残る共有ランキングを足す。

成功の目安:
- 知らない人同士でも同じ条件（モード・地域・問題数）でタイムを比べられる
- ランキングに載せるかは本人が選べて、載せるならニックネームを付けられる
- ランキングのサーバーが止まっていても、クイズ自体は普通に遊べる

チコが決めたこと（チャットで確認済み）:
- 保存先は Supabase
- 1ミスで失格（ランキング対象外）
- ランキングは「歴代」と「今週」の2タブ
- ニックネームは12文字まで＋NGワード簡易チェック、変なものはチコが Supabase の管理画面から消す
- ホーム画面の「プレイ」と「設定」の間に「ランキング」ボタン

範囲外: 豆知識（別の小さい変更として進める）、ログイン機能、管理用の画面づくり。

## 2. 遊ぶ側の流れ

1. **モード選択**: 「あそび方」に3つ目として「タイムアタック」を追加（説明文: 1ミスで失格。クリアタイムでランキングに挑戦）。モード・地域・問題数の選び方は今と同じ。
2. **国名表示は強制OFF**: タイムアタックを選んでいる間は「国名も表示する」を隠し、出題でも使わない（ON/OFFでタイムを比べると不公平なので）。練習/挑戦に戻すと元の設定が戻る。
3. **クイズ中**:
   - 上のバーに経過タイム（0.01秒単位、例 `12.34秒`）と `3 / 10` の進み具合を表示。
   - 計測は1問目を表示した瞬間から、最後の問題に正解した瞬間まで（`performance.now()`）。
   - 正解したら国情報（reveal）は出さず、すぐ次の問題へ。ドパガキ演出ONなら紙吹雪などはそのまま出す（進行は止めない）。
   - 途中で「やめる」を押したら記録なし。
4. **1ミスで失格**: タイマー停止。「失格…」の表示＋正解の国＋国情報＋「もう一回」「モード選択へ」ボタン。
5. **クリア**: 結果画面で
   - クリアタイム（大きく）
   - 「歴代◯位／今週◯位 相当」（サーバーに問い合わせ。失敗したら表示しない）
   - 「ランキングに載せる？」欄: ニックネーム入力（前回の名前を自動入力、localStorage の `nickname`）＋「載せる」ボタン。載せない場合は何もしなくていい。
   - 送信成功 → 「載せたよ！ 歴代◯位」＋そのランキングを開くボタン。失敗 → 理由（名前NG・通信失敗など）＋「もう一回送る」。
6. **ランキング画面**（ホームの新ボタンから）:
   - 上でモード（4つ）・地域（全世界＋6地域）・問題数（5/10/20/全部）を選ぶ。初期値は前回モード選択で選んだ条件。
   - 「歴代」「今週」タブ。上位50人を「順位・ニックネーム・タイム・日付」で表示。同じニックネームは自己ベストだけ。
   - まだ記録がなければ「まだ誰もいない。1位のチャンス！」＋その条件で遊ぶボタン。
   - 読み込み失敗時は「ランキングに接続できなかった」＋再読み込みボタン。

## 3. 構成

ファイル:
- `index.html`: 画面と遊びの流れ（既存。タイムアタックの分岐、結果画面、ランキング画面を追加）
- `ranking.js`（新規）: Supabase とのやりとりだけを担当する小さいモジュール。外部ライブラリは使わず `fetch` で Supabase の REST（RPC）を呼ぶ（CDN を増やさない）。
  - `RANKING.submit({ board, nickname, timeMs })` → `{ ok, rankAll, rankWeek }` または `{ ok:false, reason }`
  - `RANKING.top({ board, period })` → `[{ nickname, timeMs, at }]`（period は `all` / `week`）
  - `RANKING.rankOf({ board, timeMs })` → `{ rankAll, rankWeek }`
  - `RANKING.enabled`: URL とキーが未設定なら false（ボタンや欄を出さない）
  - `RANKING.checkName(name)`: 送信前の手元チェック（文字数・NGワード）。サーバーでも同じチェックをする。
- `supabase/schema.sql`（新規）: テーブル・関数・権限をまとめたSQL。チコが Supabase の SQL Editor に貼って実行する。

「board」（ランキングの区切り）は文字列 `モード:地域:問題数`。例 `f2n:asia:10`、`m2f:all:all`。
地域の英字キー: `all, asia, europe, africa, namerica, samerica, oceania`。

Supabase の接続先は `ranking.js` の先頭に定数で書く（URL `https://vgdkklvhtvcamtxwjpke.supabase.co`、publishable キー `sb_publishable_...`）。publishable キーはブラウザに載せる前提の鍵なので公開してよい（書き込み制限は下の権限設定で守る）。新形式のキーはJWTではないので、リクエストには `apikey` ヘッダーだけ付ける。

## 4. データと不正対策（Supabase 側）

テーブル `scores`:

| 列 | 型 | 内容 |
|---|---|---|
| id | bigint（自動） | |
| board | text | `f2n:asia:10` など |
| nickname | text | 1〜12文字 |
| time_ms | integer | クリアタイム（ミリ秒） |
| questions | integer | 問題数（`all` の場合の実数） |
| created_at | timestamptz | 登録日時（サーバーの時刻） |

権限:
- `scores` は RLS 有効、anon（publishable キーでのアクセス） からの直接 SELECT / INSERT / UPDATE / DELETE はすべて不可。
- anon が呼べるのは下の3つの関数だけ（`security definer`）。

関数:
- `submit_score(board, nickname, time_ms, questions)`: 次のどれかに当たれば理由付きで拒否、通れば登録して順位を返す。
  - board の形式が不正（モード・地域・問題数が決まった値以外）
  - ニックネームが前後空白を除いて1〜12文字でない／NGワードを含む（全角半角・大文字小文字をそろえて判定）
  - `time_ms < questions * 400`（1問0.4秒未満はありえない速さ）または `time_ms > 3時間`
  - 同じ board・同じニックネームで10秒以内に送信済み
- `top_scores(board, period)`: 同名は最速1件にまとめて、速い順に50件。`week` は日本時間の月曜0時以降の記録だけ。
- `rank_of(board, time_ms)`: 自分より速い自己ベストを持つ人数＋1 を、歴代と今週それぞれで返す。

限界（割り切り）: ブラウザの開発者ツールを使えば偽のタイムは送れる。変な記録は Supabase の管理画面（Table Editor）からチコが行を消す。

## 5. エラー時の動き

- `ranking.js` の通信はすべて8秒でタイムアウト。失敗してもクイズの進行には影響させない。
- Supabase の無料プランは1週間アクセスがないと一時停止する。停止中は「接続できなかった」表示になるだけ。
- 接続先が未設定（`RANKING.enabled === false`）のときは、ランキングボタンと「載せる」欄を出さない。タイムアタック自体は遊べる。

## 6. 確認方法

- クラウド側の Playwright で `ranking.js` の通信先を偽物に差し替えて画面確認（スマホ幅・PC幅）:
  - タイムアタックのクリア → 名前入力 → 登録 → ランキング表示
  - 1ミスで失格
  - 名前NG、通信失敗、記録ゼロのランキング
  - 練習/挑戦の動きが今まで通りか
- `supabase/schema.sql` は、クラウド環境で PostgreSQL が使えればそこで流して関数の挙動（弾く条件・同名まとめ・今週の区切り）を確認する。使えなければチコの Supabase に入れた後、管理画面から数件テスト送信して確認する。
