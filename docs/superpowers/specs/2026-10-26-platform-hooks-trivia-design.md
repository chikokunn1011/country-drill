## 2. 共通フック（RPG 設計 §10.2 の H1〜H9 を正とする）

- 中身は RPG 設計 §10.2（H1〜H9）と §10.3（イベントの約束）、バッジ設計 §8・§9.2 のとおり。食い違いがある箇所は次のとおりに決める:
  - `drill:book-open` は バッジ設計 §9.2 の出し方（一覧のカードで詳細を開いたとき／地図で国をタップしたとき。検索で自動選択したときは出さない）
  - `toast()` の CSS はバッジ設計 §5.3（画面の上に出す版）を index.html の共通 CSS に入れる。`#toasts` の作り方は RPG 設計 H2
  - `registerScreen(name, render)` は section が無ければ例外（RPG 設計 H2）
  - `endGame(outcome)` が `drill:result` を1ゲームにつき必ず1回だけ出す（RPG 設計 H8）。outcome は `clear` / `fail` / `quit`
  - PC レイアウトの `#topbar-extra`（PC 設計 §3.2）がまだ無ければここで足す
  - 結果画面の差し込み口 `#r-ext`（RPG 設計 H7）は PC 設計の `#r-side` の中に置く
- `docs/events.md` を新しく作り、イベント名・detail・出すタイミング・「1回だけ」の保証を表にする（RPG 設計 §10.3 とバッジ設計 §8 をまとめたもの）。RPG とバッジの実装はこれに従う。
- 守ること: 今のテスト（unit / e2e / SQL）が全部通る。スマホと PC の見た目が変わらない。タイムアタックの計測に影響しない（リスナーが無い状態で計測が同じ）。

## 3. 豆知識

- データ: 事実チェック済みの 779 件（195か国すべて、1か国3〜4件、種類は `flag` 国旗 / `geo` 地理・自然 / `culture` 文化・食・歴史）。元データは `/mnt/project-files/country-drill-features-20261026/trivia_facts_checked.json`（`{a, k, t, note}` の配列）。
- 新しいファイル `trivia.js`: `window.TRIVIA = { af: [{ k: 'flag', t: '…' }, …], … }`（`note` は入れない）。ISO の順に並べる。生成用のスクリプトは `tools/make_trivia.py` に置く（元データの JSON を読み、`trivia.js` を書く）。
- 表示:
  - **クイズで正解したとき**の答え合わせ（`factsHTML` の下）に、その国の豆知識を**ランダムに1つ**。種類のラベル付き（🏳️ 国旗 / 🗺️ 地理 / 🍜 文化）。直前に出したものと同じ文は避ける（その国に2件以上あれば）。
  - まちがえたとき・タイムアタック（正解で答え合わせを出さない）・失格画面には出さない（チコの言葉どおり「正解して」出る）。
  - **図鑑の詳細**（一覧・地図の両方）には、その国の豆知識を**全部**、種類ラベル付きで出す。
  - `trivia.js` が読めなくても今までどおり動く（豆知識の欄が出ないだけ）。
- PC レイアウト: 3列のときの答えの列は高さの予算がある（PC 設計 §4.2・§5.4）。豆知識を足しても **1366×657 と 1920×1080 でクイズがスクロールしない**こと。収まらなければ答えの地図を小さくする側で調整する。スマホは今までどおり下に伸びてよい。
- 文字は `esc()` を通す。

## 4. 結果画面の連打対策

- タイムアタックの最後の問題を素早く2回タップすると、2回目が結果画面のボタン（もう一回・載せる）に当たることがある。結果画面を出してから **250ms** は結果カードのボタンを押せないようにする（クイズの選択肢と同じ時間）。キーの押しっぱなし（`e.repeat`）も無視する。
